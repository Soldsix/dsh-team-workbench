# 验证码与多阶段挑战

先记录供应商、产品/SDK 版本、Web/App/小程序客户端、站点动作和测试配置。以可重现的授权测试实例建立挑战记录；公开演示和测试模式的结论只适用于对应配置。新题型先观察输入、动作、票据和后端判定，不套用旧题型参数。

## 逐层研究

1. 按题型记录字符、点选、滑块、旋转、拼图、轨迹、音频、动态多阶段、无感评分、JS/WASM 计算或跨设备证明。采集原始媒体、尺寸、缩放、坐标系、事件时间和刷新关系；同一挑战的资源、轨迹和结果使用同一编号。
2. 描述状态机：初始化、获取挑战、交互/计算、提交、得到票据、服务端校验、业务操作、过期/升级/重试。每一转换记录绑定的站点、动作、账号、设备或会话，以及有效期与可重复性。
3. 将感知正确、客户端回调、票据生成、后端校验和业务成功分开观测。前一项通过不能推断后一项；若服务端只在提交业务请求时返回拒绝，追查该请求所带上下文。
4. 受控实验一次改变一个条件：尺寸/缩放、交互顺序、刷新、时间、会话、设备、过期或网络失败。建立正常与失败样本，并记录每次请求和服务器结果。涉及真实用户操作的流程，保留可供人工完成的路径。
5. 对具体 SDK 的服务端校验、配置参数和最新题型查当前官方文档与发布说明；记录查阅日期和适用版本。媒体识别和动作生成只能依据当前样本验收，不能由文档推断真实策略通过率。

## 故障分类

| 现象 | 核对对象 |
|---|---|
| 图像识别稳定而提交失败 | 坐标变换、动作顺序、票据关联和时效 |
| 客户端显示成功而业务失败 | 后端二次校验、动作/站点绑定及风险决策 |
| 首次成功、刷新后失败 | 挑战编号、旧票据、缓存及状态更新 |
| 测试环境成功、目标环境失败 | 产品版本、场景配置、域名与后端校验差异 |
| 新题型无法归类 | 保存状态与网络序列，按实验规范建立新方法卡 |

## 交付与验收

交付题型及版本矩阵、挑战状态图、媒体和事件格式、服务端校验路径、成功/失败样本、环境范围及未解决的策略变量。验收同时核对用户可见结果和服务端业务结果，不用单次回调代替完整验证。
