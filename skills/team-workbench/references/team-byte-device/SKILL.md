# 字节系设备注册与请求签名

“七神”是社区研究中对一组字节系网关参数的称呼，不能作为固定数量、固定算法或跨端通用规则。按抖音/TikTok、Android/iOS/Web、应用与 SDK 版本、地区、业务场景分别登记样本。优先回答当前请求需要哪些状态和计算；参数名称只用于定位。

## 研究顺序

1. 保存原始包摘要、应用签名及版本、设备/安装状态、业务请求和授权测试环境。建立首次启动、注册成功、已有注册、续期、清除状态、应用升级和失败恢复的请求时间线。
2. 从业务请求向前追踪注册返回值、远端配置、安装标识、设备字段、会话令牌及请求签名输入。对每项标注生成位置、持久化位置、有效期和版本依赖，不把名称相近的字段合并。
3. 分开观察 Java/Kotlin 或 ObjC/Swift 层、JNI/Native 层、可能的 VM 层及网络序列化。跨层记录调用输入输出的精确字节与线程/时间；Native VM 的指令恢复按需选 [虚拟机分析](../team-vm-reverse/SKILL.md)。
4. 对目标业务请求建立路径、查询、正文、头字段、时间、随机量、注册状态和签名输出的因果表。用可控输入对照定位第一处差异，避免从某一个网关参数推断所有计算已恢复。
5. 先在离线向量验证计算，再在授权测试环境验证注册、状态更新和业务接受。新设备与旧设备、过期/无效状态及并发请求分别验收。真实服务拒绝时区分计算、注册、会话、业务条件和策略判定。

## 交付

交付端/版本矩阵、状态机、跨层调用图、字段来源、签名分层向量、失败样本和协议结果。每个参数写明“已观察输入”“已独立复现”“已服务端验证”的最高等级。未观察到的参数及服务端规则保持未知；当前项目的纯算要求按 [纯算验收](../team-offline-computation/SKILL.md) 另行核对。
