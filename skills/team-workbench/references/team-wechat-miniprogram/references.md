# 微信小程序专业参考

按任务选择本参考中的阶段，不要求所有成员同时加载所有方向。

## 必要条件与工具

记录授权对象、AppID/版本、源代码或测试包、开发框架、基础库、开发者工具入口、真机平台、测试账号、可调用工具和交付目录。用户已经确认的范围不重复询问；没有设备、代码或权限的分支明确记为未验证。

开发者工具可用、自动化端口可达、正确项目已打开、真机测试通过分别验证。Android 真机和模拟器先核对 adb 序列号，多个设备必须显式选择。Frida 需要客户端/服务端版本与 ABI 对齐，注入只对授权测试应用；电脑上有命令并不意味着设备上的流程已完成。iOS 动态测试单列设备和 Mac 依赖。

## 静态分析路线

从 app.json 与分包找到实际入口，列页面路由、组件、事件、状态和请求封装。框架生成代码先映射回源码层，再追编译产物。归纳网络调用、数据格式、错误码、重试、缓存、环境开关与登录状态。混淆代码固定原样本摘要，记录恢复名称的证据；复杂 JS/WASM/VM 另选对应专业模块。

每个关键请求保存：调用位置、触发操作、参数来源、序列化、编码/摘要/签名顺序、动态输入、会话要求、响应业务码、字段落点与异常分支。函数名或文章里的算法称呼不是实际等价实现的证据。

## 授权抓包与动态核对

先通过开发者工具网络面板获得一个确定的 UI 操作基线；真机上核对是否同一包和环境。采样有操作 ID、设备、基础库、时间、连接方式和会话状态。对自有调试版优先源码日志与测试配置；生产保护、证书和设备完整性检查不能靠随意关闭来替代验证。

把接口研究拆为字段来源、请求生成、响应解释和服务端状态。一次只变一个主要变量：首次登录、续期、清理缓存、退出、网络变化、账号差异。保存失败样本与返回码，不把 HTTP 200 当业务成功。

抓包代理和开发者工具配置只用于项目环境，不修改全机网络后影响其他任务。测试 token、个人数据和上传密钥不进共享提示词；报告提供脱敏样例和安全引用位置。

## 登录态与业务协议

区分短期登录凭据、服务端会话、用户标识、应用内部设备/安装标识与接口权限。登录流程的状态变化要由服务端或可复核业务响应确认；同样的请求参数在另一账号或环境可能没有同样含义。公开可访问数据与登录后资源分别证明，不能把登录失败通过重试当权限测试结论。

开发实现检查会话过期、重新登录、并发刷新、重复业务提交和幂等。授权采集先验证单条字段、空值与分页结束条件，再构建限速、增量游标、去重、重试、断点和异常隔离；不能把无法稳定握手的路线直接扩成批量任务。

## 小程序开发与 UI

明确页面状态、组件接口、网络错误反馈、权限提示、缓存与恢复。WXML/WXSS 和 JS/云函数分配独立文件，公共类型由唯一负责人维护。覆盖冷启动、下拉/分页、分包失败、弱网、后台恢复、账号切换、深链和平台差异。使用本地可复现 fixture 验证数据层，再用真机核对平台行为。

## 官方自动化与交付

[miniprogram-automator](https://www.npmjs.com/package/miniprogram-automator) 用于开发者工具自动化；先查实际支持版本、CLI 路径与端口。[miniprogram-ci](https://www.npmjs.com/package/miniprogram-ci) 支持构建、预览和上传，上传密钥与 IP 白名单按项目实际配置。自动预览不等于公开发布，发布需要项目已确认的动作范围。不得将测试状态写成生产发布完成。

官方文档如无法访问，记录不可达并核对官方包与源码；不从过时二手教程硬写固定版本。每次项目记录核查日期和实际版本，而不是长期宣称“最新”。

## 产物与验收矩阵

产物包含项目/包指纹、调用图、接口字段表、状态机、采样清单、实现或研究结论、自动化回执与真机矩阵。矩阵按 Android/iOS、基础库、包版本、账号、网络、冷/热启动排列。标记资料推断、模拟器复现、真机复现、服务端确认四个等级。

关键验收包括：输入与环境版本一致，字段有来源，签名样本有独立测试向量，失败路径有处理，数据采集不重复且可续接，真实 UI 有错误与恢复入口。独立验证成员在不同输入或保留样本上检查；未做到的端或设备明确留项。
