# 微信小程序工作流

## 起点确认

明确做开发、已有项目故障、自己应用的接口研究或授权数据采集；确认 AppID/包版本、原生或框架、基础库、开发者工具、真机、账号与目标接口范围。没有样本先定位合法输入，不假称已解包。微信小程序与普通浏览器的 DOM、网络、存储和登录环境不能混用。

## 阶段流程

1. 清点 app.json、project.config.json、分包、组件、npm、云函数和可用 source map；固定源代码/样本摘要。记录入口、页面、事件、状态与服务调用。
2. 静态从页面事件追到公共请求封装、wx.request/uploadFile/downloadFile、WebSocket 或云函数；整理参数来源、签名输入、编码顺序、失败码与数据落点。研究只保留样本能支持的结论。
3. 用授权测试账号与开发者工具网络面板建立基线；必要时在自有调试环境和真机记录请求/响应。记录操作、设备/基础库、会话与时间，脱敏 token 和个人数据。
4. 分析登录/续期/失效、缓存与重试状态；以业务响应和服务端记录核对成功。域名配置、代理、证书、模拟器与真机差异分别判断，不能把关掉校验后的成功当上线可用。
5. 开发/修复先约定接口和状态，页面实现、云函数与测试分开写入。采集先证明允许访问与单条正确性，再设计限速、增量、幂等、失败续接和字段质量。
6. 实际可用时采用官方 miniprogram-automator 做开发者工具测试，miniprogram-ci 做构建/预览/上传；部署动作与密钥按项目范围管理，不把凭据放入提示词。

## 必须交付

项目/样本清单、调用链、接口字段、登录状态机、证据包、可复现步骤及未验证条件。开发项目另交付加载/空态/失败/权限拒绝 UI、真机矩阵、构建结果和回滚。

## 验收

模拟器与真机分别通过；冷启动、断网、过期会话、分包加载、平台差异、重复提交和隐私字段检查有证据。自动化端口可达不等于应用功能通过。按需读 [详细步骤与模板](references.md)。
