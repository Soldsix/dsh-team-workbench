# 设备注册与协议

沿用本任务已确认的对象与操作范围；团队交接条件缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。将设备指纹、安装身份、账号凭据、会话令牌、完整性证明分别命名；不要把“获得一个返回值”当作设备注册全部完成。

## 恢复过程

1. 记录触发事件、请求顺序、方向、连接复用、时间和应用状态。把 TLS 传输封装、应用层加密、压缩与序列化分层保存；PCAP 看不到明文时结合合法客户端观测，不猜测内容。
2. 按状态整理首次初始化、已有缓存、挑战过期、注册成功、续期、失败重试、注销/清理、清除数据后重新注册及应用升级。记录每个转换的条件、输入、输出、持久化变化和服务端可见状态。
3. 字段表写清大小、类型、字节序、编码、默认/缺失值、时间单位、随机量、计数器和取值依据。Protobuf 字段号不等于业务含义，需消息样本与调用侧互证。
4. 对签名规范化记录路径、查询顺序、正文原始字节、头字段、nonce 和时间；算法部分交给 [加密参数](../team-crypto-parameters/SKILL.md)。不要在证据中复制真实账号密钥。
5. 搭建本地协议测试端或明确授权的测试服务，验证正常序列、重复请求、乱序、超时、网络中断、过期数据、不同版本与拒绝结果。影响线上身份或状态的请求只在已确认范围内执行。

## 复现与团队分工

客户端采集组提供精确上传前数据，协议组负责字节与状态，服务端验证组负责接受/拒绝的依据。共享请求编号和时间线；区分 HTTP 成功、业务成功与身份实际绑定。只靠固定响应的替身测试不能说明真实服务接受。

实现最小编解码器和状态机，记录未知字段并保持原字节，使用独立样本验证。每个重试明确是否幂等；结果未知的有状态请求先核查服务状态，不直接重复注册。

## 验收

交付协议说明、状态图、字段表、有效与无效向量、可运行本地夹具和异常行为。未知服务端规则、测试替身及真实服务观测分开标记，复核者能按原始字节验证每一步。需要脱离浏览器完成计算时，另按 [纯算与协议直连](../team-offline-computation/SKILL.md) 对运行依赖、独立样本及服务端接受分别验收。
