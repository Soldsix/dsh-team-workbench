# 工具健康与错误恢复

## 适用条件

工具未知、成员无法搜索、MCP 断连、命令报权限、工作区过大或反复出现相同参数错误时加载。目标是用最小检查定位原因，避免“换一种写法再碰运气”。

## 健康分层

分别记录：程序是否存在及版本、宿主是否接入、当前成员是否能看到工具、目标是否允许该操作、运行依赖及凭据是否就绪、最小调用是否成功。安装成功不能代替后面五项检查；所有健康结果记录核查时间和适用会话。

## 通用流程

1. 先查 team_help 的 tools、network 或 recovery 主题，再看当前任务与目标资源。调用前读取真实参数 schema；不猜工具名称、provider 或不存在的后台查询接口。
2. 工具缺失时检查插件状态与成员 allowlist；权限被拒时核对具体路径、URL 来源、搜索开关和执行方式。受限网络工具与不透明命令权限不同，不通过把资源全部改成星号来假装修好了。
3. 同一错误只做一次原因分类。将错误代码、最小输入、当前配置版本和建议下一步记录下来；没有状态变化不要重复调用。
4. Windows 默认使用宿主已配置的 PowerShell 7。每个命令明确 cwd、环境、参数、超时、编码及输出上限。简单文件操作用原生工具；复杂参数使用任务专属脚本，避免混用 Bash、cmd 与 PowerShell 语法。中文路径、空格、引号和 JSON 先用无害输入验证。
5. MCP 按具体工具准入。完整权限服务可能绕过工作区隔离，未验证 OS 约束时不能标为严格隔离。浏览器、设备和账号只能由当前资源 owner 控制。
6. 网络失败分别判断解析、连接、TLS、来源限制、凭据、限流、额度或上游响应；保留来源与时间。模型没有内建搜索并不表示 DSH 没有搜索工具。

## 后台与恢复

启动作业必须拿到任务编号，检查查询、取消与恢复工具均可用。等待交给程序，不用模型反复空转。超时或断线先核对在途状态；重启后有副作用操作不能盲目重放。工具暂不可用时，继续其他独立任务。

## 交付与验收

交付工具矩阵、最小调用回执、诊断和恢复步骤。用正常、失败、取消、重连四条路径验证。工具可见、范围合规、输出可读取且结果符合验收，才标记工作流可用。凭据只能保留安全引用，不进入聊天、报告或公开测试样本。

## 来源与版本

当前宿主工具说明及相应工具官方文档；版本 1，2026-11-07。更新时固定实际工具版本，不复用过期参数。
