# 纯算与协议直连

本项目的纯算目标是：最终计算不调用浏览器或 DOM 补环境，允许业务所需的网络握手，动态输入具有明确来源。研究阶段使用浏览器、设备或插桩不影响最终分类；交付时按真实运行依赖区分“离线计算”“协议直连”“仍需浏览器/设备”。

## 输入清单与实现

1. 从当前样本记录版本、业务场景、函数入口、精确输入字节、输出字节和已知依赖。将输入分为业务字段、请求上下文、设备信息、服务端下发值、时间、随机数、会话状态和秘密材料；每项写明来源、生命周期、取得方式及缺失后的行为。
2. 对每层建立可重复向量：字段规范化、序列化、编码、压缩、密码计算、封装。逐层比较原实现和目标实现的长度与字节；先修第一处差异，再比较下一层。
3. 将当前版本规则、动态输入提供者及网络协议状态分为可替换模块。计算函数只接收显式参数并返回结果或明确错误；网络客户机负责握手、状态更新与重试。受控固定时间和随机量只用于测试向量。
4. 确认 JS 到目标语言的语义：数值位宽、溢出、字符串编码、属性顺序、浮点格式、URL 编码、重复键、空值及缺失值。使用成熟密码库实现标准算法；自定义运算保留可核对的中间结果。
5. 在无浏览器、无 DOM 的干净进程中运行独立向量，随后使用未参与开发的样本检查正常、边界、异常与版本变化。授权服务测试再检查握手成功、业务接受、状态续期、过期及网络失败；本地匹配与服务端接受分别报告。

## 失败分流

| 失败层 | 处理 |
|---|---|
| 固定向量不一致 | 找首个不同字节和上游输入，不反复调整末端签名 |
| 固定向量一致而新样本失败 | 核对版本、动态输入来源及未覆盖分支 |
| 签名一致而协议拒绝 | 检查设备注册、会话绑定、过期和业务条件 |
| 并发时失效 | 检查计数器、Cookie、令牌更新的所有权和原子性 |
| 仍需要浏览器 API | 标记该具体依赖，恢复其输入或明确当前完成等级 |

## 交付与验收

提供运行依赖清单、动态输入表、版本识别、逐层向量、无浏览器运行命令、独立样本结果及协议服务结果。声称“纯算完成”时，验收者可在不启动浏览器或 DOM 的环境重复计算；声称“协议直连完成”时，还须完成声明场景的握手和业务验证。
