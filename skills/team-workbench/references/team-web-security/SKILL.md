# Web 与 API 安全测试

首先沿用本任务已确认的目标和范围；缺失时集中确认对象、测试账号、允许操作、窗口与速率，团队交接方法缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。对用户指定域名的授权不自动包括其 CDN、第三方登录或共享云资产；新证据不能替代范围决定。

## 测试路径

1. 盘点路由、API、角色、租户、数据流、上传、异步任务、缓存和反向代理。先从项目代码和用户提供资料建立攻击面，再进行获准的线上观测。
2. 按用户目标选择认证、会话、授权、输入处理、业务逻辑、文件、缓存、跨源与依赖检查，使用 [OWASP WSTG](https://owasp.org/projects/web-security-testing-guide) 作为检查来源，记录与实际版本的对应。
3. 对 CVE 核对上游公告、受影响版本、配置、可达路径和补丁。仅版本匹配不能判定可利用；在本地等价环境建立最小复现，再按已确认许可验证目标。
4. 分配只读发现、漏洞验证、修复分析与独立复核分支，统一请求/漏洞编号。确认可能写入状态或读取敏感数据的操作是否已获准；数据库验证优先使用合成记录和最小证据，扩展数据量需要对应范围。
5. 记录请求、响应、身份、前后状态与清理结果。CTF/本地靶场的 WebShell 或数据库导出练习仅限隔离目标与测试数据，不能将演练结果写成真实资产已攻破。

## 验收

每项发现写明前提、复现步骤、影响、证据与置信限制。区分已确认、待确认和不适用；避免只报告扫描器输出。修复验证至少包含原复现失败和正常业务继续可用，结束后核对测试账号、文件和任务状态。没有目标样本时交付本地测试方案与夹具需求，不启动无目标扫描。
