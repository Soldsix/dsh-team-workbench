# Akamai 浏览器 SDK 研究

用于用户指定站点或离线样本中的 Akamai 相关脚本和 `_abck` 现象。先读取本项目确认的域名、路径、账号、测试窗口、可访问的 CDN 配置与允许操作。站点使用 Akamai 不等于其所有子域名、供应商接口或其他客户资产都在同一范围。没有样本时，先准备观测表和本地模拟夹具，不把模拟结果写成真实 Akamai 算法结论。

## 起点与分工

确认要回答的是加载失败、Cookie 生命周期、采集字段、编码变换、版本差异、误拦截，还是与自有系统集成。收集浏览器及内核版本、站点环境、脚本响应与摘要、请求记录、Cookie 属性和服务端配置版本；敏感值在共享记录中脱敏，并保留可验证的摘要。先读取已有实验编号与结果，复用相同版本的证据。

并行时将脚本和配置版本、浏览器执行流、Cookie 变化、网络时序、环境字段、行为事件、跨环境对照和独立复核分给不同成员。每人使用同一时间基准、输入版本、字段命名和证据格式。写入目标或测试浏览器配置由一人占用；只读样本可以共享。组长为下级和孙级指定独立假设与交付物，避免多人重复抓同一页面。

## 观测与判断

1. 从页面加载开始记录脚本来源、重定向、缓存、动态加载、Worker、iframe 与执行入口。脚本哈希变化时建立新输入版本；不能把不同发布版本的调用栈拼成一条链。
2. 对一次全新会话和一次已有状态会话分别记录 `Set-Cookie`、脚本可见 Cookie 写入、请求携带的 Cookie，以及清除、过期、重定向和异常响应后的变化。以观测到的设置位置判断值的来源，不从 `_abck` 名称推断生成算法或有效性。
3. 在受控浏览器中定位采集、变换、编码、缓存与网络发送的边界。用最小日志或断点记录输入输出、调用栈和发生时间；先保存无插桩基线，再比较插桩是否改变时序或结果。将浏览器 JS 可见字段、请求头、TLS 或边缘判定分开记证据。
4. 每个实验只改变一个变量，例如浏览器版本、存储状态、语言时区或交互序列。记录预期、实际请求、响应、Cookie 属性、状态码（含 428 一类挑战响应）及重复次数。对“值变化”“服务器接受”“业务页面可用”分别给出结论；其中一项成立不能推出另外两项成立。
5. 需要比较实现时，先用自有离线夹具验证字段处理和编码假设，再在已确认范围内核对真实样本。版本、配置或服务端判定未知时保留未知项，不把某次样本匹配概括为稳定算法。

## 交付与验收

交付资源清单及哈希、页面到网络的时序图、字段来源表、Cookie 状态表、单变量实验记录、可复核的脱敏请求证据、失败尝试和未证实假设。每条结论标明对应脚本版本、浏览器环境、样本编号和复核人。问题修复类任务另附同环境回归结果；研究类任务说明已覆盖及未覆盖的环境。

公开资料只作产品行为和配置入口的参考，不当作当前站点实现证据。项目开始时核查 [Akamai Bot Manager 检测方法](https://techdocs.akamai.com/cloud-security/docs/detection-methods)及[Bot Manager 客户端安全配置](https://techdocs.akamai.com/terraform/v10.1/docs/bmgr-ds-client-side-security)的当前版本；实际配置以用户可访问的站点记录为准。用户称呼的“2.0/3.0”须对应脚本摘要、客户端配置和场景，不能以标签合并测试结果。需要更广的浏览器采集链时按需选 [网页指纹](../team-web-fingerprint/SKILL.md)，需要单独追踪编码与摘要时再选 [加密参数](../team-crypto-parameters/SKILL.md)。
