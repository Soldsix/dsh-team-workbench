# 部署与故障恢复运行手册

## 环境清单

项目/服务、环境等级、宿主 OS、运行时/依赖版本、启动方式、实际进程与端口、数据目录、日志、配置来源、凭据引用、外部服务、健康检查、当前任务和负责人。连接密钥的值不放进 Session、截图或报告；引用名称与可用状态即可。

自有 DSH 使用受支持的 dsh profile 启动；构建与源码运行模式不能混用，旧模式、插件、技能与 MCP 在兼容矩阵里逐项记录。独立端口测试使用独立数据副本，不让测试重载用户当前业务。

## 变更计划

变更对象和原因、固定产物摘要、配置差异、持久数据变化、影响范围、实施窗口、执行顺序、可观察成功条件、停止阈值、备份与回滚、责任人和用户确认记录。具体可执行计划先准备完成；已获明确授权的步骤不用再重复问许可，真正缺失的条件才集中提问。

## 备份与数据兼容

会话日志、投影/缓存、数据库、模式、人设、模型连接引用、插件清单和文件成果分别清点。使用应用支持的一致备份或明确停写；不停写复制数据库可能不完整。恢复演练在独立目录验证应用能读、历史能重建、模式与工具能加载。

历史 Session 世代不能移动、覆盖或删除来制造兼容。升级前数据与升级后新写入分别保留；代码降级不等于数据可以降级。迁移成功、回滚代码、恢复数据和保留新业务记录都有具体流程。

## 发布与灰度

检查构建、聚焦测试、配置解析、启动及关键业务；再分流或独立端口比较新旧版本。预先约定观察时间、错误/延迟/资源指标及阈值，不能看到一个健康响应就全量切换。[Google SRE 灰度发布](https://sre.google/workbook/canarying-releases/) 说明了比较发布版本与控制版本的价值；采用时按项目业务和状态共享条件调整。

服务有独立可管理的启动、停止和恢复入口，启动回执写 PID、端口和版本。重复启动先检查服务归属与锁定，不能杀不属于该项目的进程。外部工具/MCP 连接、成员隔离工具和真实请求分别验证，安装成功不是验收通过。

## 故障响应步骤

1. 记录发现时间、影响、版本、请求/任务 ID、最近变更和用户可见症状。保留原始日志和当前数据。
2. 先止损：暂停受影响队列、限流、退回稳定版本或隔离异常依赖；其他独立服务继续。动作须在已确认范围内。
3. 将假设按证据和影响排序，使用一项最小验证区分；重复读同一日志不产生新证据。区分 DNS/TLS、凭据、账户额度、数据版本、应用异常、进程和资源耗尽。
4. 核对后台操作实际状态与副作用，再决定重试。恢复原成员、任务和检查点，不能默认重做所有工作。
5. 达到停止/回滚条件按计划执行，并验证业务、数据和任务接续。保留恢复前后回执和新增数据。
6. 恢复后观察指标，关闭事故需真实成功证据。根因、临时缓解、永久修复与未确定事项分开，后续有负责人和验证期限。

## 演练与验收

在测试环境模拟依赖断连、额度耗尽、进程异常、磁盘不足、配置错误、迁移失败和旧会话恢复；测试取消、恢复、重复派发与幂等。不能为了演练故障影响真实生产服务。完成记录恢复时间、丢失/重复操作、遗留进程和人工步骤。

实际交付包括兼容矩阵、变更与部署回执、健康与业务证据、备份恢复结果、回滚入口、未测试外部依赖及风险。静态检查和回放测试不能证明所有真实提供者或用户业务已通过。
