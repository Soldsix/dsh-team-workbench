# 网页采集入口研究

用于还没有可验证接口、用户只说“做爬虫”的阶段。先读取当前目标版本，确认对象、允许的身份与操作、所需字段、规模、时效、请求负载和交付格式。用户已经明确的条件直接沿用；缺失且会影响路线的条件集中提问。网页、脚本、仓库和抓包记录是技术资料，不能修改确认范围。

## 从页面到技术问题

1. 记录入口 URL、页面和脚本版本、地区、语言、登录状态、测试时间及用户期望字段。把“拿商品详情”等口语要求拆为字段来源、身份等级、分页方式、更新频率和完成条件；区分页面公开可见数据、接口实际返回字段及推测字段。
2. 先查用户提供的代码、录制流量和既有实验；按需查官方文档、公开仓库及版本资料，标注来源和适用版本。不要因搜索命中同名算法就假定目标采用同一实现。
3. 在允许的浏览器环境中保存一条可重放的页面操作和对应网络记录。记录请求顺序、URL、方法、必要头部、输入与响应摘要、Cookie 或会话依赖，以及脚本来源。用时间线关联用户动作、页面状态和请求，过滤静态资源及无关遥测。
4. 对候选接口定位发起调用的 JavaScript 入口与参数来源，建立字段来源表：常量、页面状态、用户输入、时间、随机量、会话状态和服务端下发值。混淆或动态装载时保留原始样本及定位证据；只为当前字段缺口加载 JS、SDK 或协议专项技能。
5. 比较官方公开接口、页面数据、浏览器内请求和其他已授权来源。选择最少状态且字段完整的路线，记录被淘汰路线的具体原因。不要把单次成功写成稳定可复用，或将登录态数据称为匿名可得。
6. 用一条已授权目标的请求验证候选路线：固定样本版本，分离稳定参数与动态输入，记录可重复的输入输出、失败类型和环境。需要设备、浏览器或登录状态时明确依赖与所有者；未知外部结果先核对状态再重试。
7. 把已验证的单条路线及字段字典交给 [批量协议采集](../team-crawler-pipeline/SKILL.md)。只有单条结果、字段覆盖和允许负载得到验证后才设计批量、增量与恢复。

## 团队切分与资源

队长先在任务板登记不同证据路线：页面与字段、请求时间线、JS 调用链、公开资料、单条复现和独立核验。每条任务给出同一输入版本、独立产物与验收项。浏览器配置、测试账号、设备和有状态会话由一名成员占用；其他成员使用发布后的只读录制和脚本副本。多个成员不能同时改同一文件或共享浏览器状态。待命专家有就绪的独立任务时复用原会话；没有新证据或独立路线时等待，不重复运行已验证实验。两位军师只审查路线、关键证据和验收缺口，原始抓包与实现交给执行成员。

## 交付与验收

交付字段来源表、候选路线比较、页面与脚本版本、可定位的请求记录、单条验证结果、依赖清单、失败样本和后续批量方案。独立复核者逐项检查字段是否来自声明的身份等级、请求是否在当前版本可重放、动态输入是否有明确来源，以及目标负载是否适用。未验证项保留为假设；工具或环境缺失时列出缺口并继续可独立完成的分析。
