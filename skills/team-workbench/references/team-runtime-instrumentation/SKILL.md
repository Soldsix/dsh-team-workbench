# 运行时观测

沿用本任务已确认的目标与设备范围；团队交接条件缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。先写清“观察哪个函数/字段以区分哪两个假设”，避免全量 Hook 和海量日志。默认保持被观测程序的参数、返回值和副作用；需要改变行为的实验单独标明。

## 准备与执行

1. 核对 Host、目标端与桥接库版本、架构、模块和进程身份。Frida 脚本按当前 [官方 API](https://frida.re/docs/javascript-api/) 与实际版本编写，不套用过时静态方法。
2. 先运行无观测基线，记录输出、时延、线程和异常。按实际模块/类加载事件设置观测，避免固定休眠猜测时机；处理重复加载和进程重启。
3. 最小记录参数、结果、调用栈与请求关联编号。对指针核对长度、可读区间与生存期；字符串区分编码，异步回调不要保存已失效的内存引用。
4. 处理重入、并发回调、异常与日志回压；设定受当前任务约束的采样/字节上限，记录丢失计数，不能默默丢证据。日志写入本地项目受控目录。
5. 对比观测前后结果和性能，必要时改用断点、平台跟踪或更窄探针。脚本自身异常与目标异常分别标记。

## 清理与验收

正常结束、取消和失败都解除本任务安装的探针、恢复本任务修改的设置并保存未完成状态；不关闭不属于本任务的进程。多人共享设备时统一设备占用与采样计划。

交付带版本条件的脚本、观测点表、原始日志、关联方法和基线差异。工具无报错不能证明目标路径被执行；必须有该路径触发证据与未触发反例。后续结论遇到对照设计或证据冲突时，再补读 [实验规范](../team-experiment/SKILL.md)。
