# 网页设备指纹 SDK

先按本任务已确认的目标和范围确定网页分析问题；只有需要规划跨平台整体链路时才补读 [设备指纹总流程](../team-device-fingerprint/SKILL.md)。保存 HTML、脚本及动态加载资源的实际版本与摘要；记录浏览器、内核、配置、权限、语言、时区、图形环境和页面源。优先已有浏览器工具，必要时检查 DevTools/CDP 是否支持所需观测。

## 分析步骤

1. 从脚本加载和公开入口定位初始化、配置拉取、采集触发及结果回调。枚举 iframe、Worker、Service Worker、动态模块和 WASM；相同函数名在不同执行上下文中不能视为同一实例。
2. 整理环境字段：显示与视口、语言与时区、浏览器能力、图形/音频输出、字体探测、存储状态、硬件能力和异常路径。只记录样本实际调用的接口，不把通用指纹清单当作该 SDK 的行为。
3. 沿字段值进入排序、缺失处理、字符串/二进制编码、摘要、缓存和上传。分别记录稳定特征、随机安装 ID、短期会话量与服务端返回值。
4. 在受控页面对关键 API 使用断点或最小日志观测，保存调用栈和输入输出。先基线后观测版本；测量注入时机、异步顺序和观测开销，避免自己改出的差异被当作 SDK 特征。
5. 对浏览器重启、隐私模式、存储清理、同型号设备、系统/驱动升级与权限拒绝做对照。区分浏览器主动降低精度、接口不可用与 SDK 处理错误。
6. 需要复现时先保留真实浏览器基线，再重建最小环境。缺失 API 明确报错，不用随意返回固定值把程序“跑通”。未见样本验证哈希与上报参数的一致性。

## 成果与验收

提交资源清单、采集字段表、初始化到上传的时序、最小复现和跨环境对照结果。对图形/音频等派生值说明渲染与计算条件；声明支持的浏览器范围及失败场景。

服务端网络特征、TLS 握手属性与网页 JS 可见值分别取证；不能仅从 JS 反推完整服务器模型。行为采集另用 [浏览器行为](../team-browser-behavior/SKILL.md)，注册与挑战另用 [注册协议](../team-registration-protocol/SKILL.md)。

可将 [FingerprintJS](https://github.com/fingerprintjs/fingerprintjs) 的开源实现用作字段处理对照，实际项目先核对版本和许可证；其开源库与商业服务分别评估。
