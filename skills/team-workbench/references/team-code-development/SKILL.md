# 项目代码开发

沿用本任务已确认的目标；团队交接方法缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。先读取项目实际架构、运行方式和现有改动。把用户场景转换成可演示的成功路径和需要保留的行为，不以重写架构代替明确需求。

## 实施步骤

1. 盘点代码、构建、依赖、测试、数据与发布方式，确定现有版本和工作区状态。用户未提交改动与旧数据分别保留，不为建立干净环境覆盖它们。
2. 按可独立验证的功能分任务，先约定接口、错误、取消、数据版本和消费方；共享文件指定负责人。使用分支/隔离工作区时写明合并顺序与共同基线。
3. 选择现有扩展点和可维护依赖。引入外部方案或版本适用性存在缺口时，按需使用 [研究规范](../team-research/SKILL.md) 核对；样例能运行和适合项目是不同结论。
4. 每步做足以验证用户行为的最小完整实现。存储变更提供备份、迁移和回滚条件；并发、缓存和后台任务明确持有者、生命周期与取消结果。
5. UI 延续现有设计、语言、键盘操作和小屏布局。默认入口直观，高级参数逐步展开；错误说明用户下一步能做什么，后台实现细节放到开发诊断。
6. 独立复核关键差异、失败路径与接口消费者；有证据的缺陷就修复，避免重复运行与本次改动无关的完整测试集。

## 验收

执行与改动相符的检查；验收指标或性能证据不明确时，按需读取 [质量与性能](../team-quality-performance/SKILL.md)。交付真实可运行的入口、功能演示、通过/未通过项、数据兼容与剩余限制；未执行部署或发布时明确保持待执行状态。跨会话复用记录缺失时，按需读取 [交付与记忆](../team-delivery/SKILL.md)。
