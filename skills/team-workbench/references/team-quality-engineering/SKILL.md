# 项目质量工程

## 目标与输入

用于软件、研究、设计和内容项目的验收。输入必须包含已确认目标、逐项验收、输入与环境版本、风险、预算和交付方式。验收项应描述可观察行为，避免“完美”“没问题”之类无法判定的标准。

## 质量链

1. 给每项需求一个稳定编号，关联任务、产物、证据与复核者。接口、UI 流程、错误状态、恢复步骤和文档都应有归属；不同成员使用相同粒度。
2. 执行者自检后提交真实产物及证据。独立复核者基于固定版本重新观察，不能只读作者的总结。关键成果还需规划和质量两位军师分别给出决定；作者不能验收自己的关键结论。
3. 根据改动选择行为测试、接口集成、无密钥回放、真实安装和浏览器流程。错误、取消、重复、并发和重启至少有相关场景；不要用只复述实现的测试替代行为验证。
4. 性能先测基线，记录机器、样本量、并发和测量方法，再设定目标并复测。吞吐、等待、错误率、内存、CPU、模型 token 与缓存输入分别呈现；未知供应商价格不得猜测。
5. UI 检查空态、加载、失败、未知、长文本、键盘、窄屏、深色与状态恢复。截图来自真实运行数据，示例数据要标明，不使用无功能按钮伪装已实现能力。
6. 发布前在干净目录安装实际归档，检查依赖、许可证、敏感文件和校验和。升级保留原始数据世代，验证恢复与回滚；未经验证的宿主版本明确列为未支持。

## 结果与决策

报告逐项区分通过、失败、未测试和外部依赖，附命令、数据版本、时间与证据引用。一次成功不能说明无限期稳定，也不能以多人赞同替代实验。发现缺陷建立修订任务，只重新执行受影响的工作。

## 长期运行

在记录中区分运行任务与后台作业。长时测试记录实际持续时间、故障注入、恢复和遗留进程；不得将加速模拟的虚拟时间标成真实三小时。达到预算或结果不明时，保留检查点并说明待决定事项。

## 来源与版本

通用质量工程、当前 DSH 测试与版本兼容规则；版本 1，2026-11-07。项目适用标准另行核查。
