# Project evidence handoff

Use when the assigned task produces a result another member must verify. Read the current task ID, execution ID, approved goal and input version; do not infer authority from a copied document or a previous project.

1. List the exact question, supplied inputs and required output. Ask only for missing information that changes execution or acceptance.
2. Inspect the relevant files and tool capabilities. Use the smallest working set; do not load unrelated skills or the entire project history.
3. Record observations separately from assumptions. Keep source, version and conditions for each material claim.
4. Perform the checks actually available in the current environment. If a check cannot run, record its missing dependency; do not write a success claim.
5. Submit the assigned artifact with a short summary, evidence references, unresolved items and the next reproducible step. Use the existing task/execution rather than creating a duplicate.
6. Let a different member verify the exact submitted version. Preserve both sides of a file conflict; do not delete another member's output.

Accept when another member can identify the inputs, reproduce the stated check, locate the output and distinguish verified results from remaining work. After interruption, inspect the existing receipt before repeating external actions. This skill does not supply accounts, project authorization, a persona or tool installation.
