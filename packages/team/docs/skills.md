# Skills 技能专册

## 概要

本版包含 55 个专业模块和一个团队入口。目录只提供名称与用途，正文按任务选择后加载；模式已有技能继续按宿主优先级解析。模块是可版本化的工作方法，不是对真实工具、模型或所有专业结果的成功保证。

## 选择与上下文

先用 team_skill_catalog 按具体问题检索，再选择一个当前流程与一至两个专业模块。每成员默认最多四个模块，并受 maxSkillSelectionBytes 限制；目录摘要不等于正文已加载。阶段切换前保存任务、输入、证据和未完成项，再显式调整技能，避免将全部历史与无关正文塞入上下文。

角色指令、模式人设和技能职责分别保存。当前成员身份、确认目标与选定技能版本在冷恢复和压缩后重新形成上下文；旧项目授权不能跨项目自动复用。某个模型的限制或意见应当记录为该模型的阻碍，不得伪装成用户改变了授权。

## V5 新增模块

- team-research-design：把口语目标变成问题、假设、控制变量、证据和停止条件。
- team-handoff-continuity：保留当前状态、失败尝试、输入版本、成果和下一步，交接时先核对再续跑。
- team-tool-health-recovery：按工具发现、准入、凭据、网络与执行层定位错误，避免同类失败反复消耗。
- team-quality-engineering：建立验收矩阵、独立验证、反例、回归与可复现交付。

## 专业方法要求

每个项目按实际样本、版本和目标范围选工作流。研究类保留原始样本、单变量实验、已排除假设及复现输入；开发类对齐需求、接口、实现、测试与交付；创作类固定人物、时间线、章节进入和离开状态并做连续性复核；运维类先诊断，再核对变更回执、健康和恢复。

公开搜索和项目下载必须符合项目范围与真实工具权限；记录官方来源、版本和核查日期。技能更新先成为候选，经示例、反例与回归验证后发布；运行中的任务使用固定版本，不在执行途中悄悄替换。

## 自定义

通过 team-workbench-skills.additionalSkillRoots 加入自己的模块目录，使用独立 providerName。编写明确的适用条件、必要提问、输入和工具、步骤与分支、交付、验收、恢复及来源。不要复制私人账号、授权、人设或项目敏感资料到可复用技能。

## 验证范围

本轮验证目录解析、按需读取、选择预算、同名模式技能、版本固定、冷恢复与正文退休。真实 Android/iOS、微信工具、浏览器环境、生产运维、商业写作效果以及特定厂商最新协议不能仅凭技能文档判为通过，需在各自授权项目中验收。
