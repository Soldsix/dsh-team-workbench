# 使用说明：从目标到交付

## 概要

安装后继续选择原来的模式和模型，再建立团队项目。模式保留自己的沟通风格与技能，团队插件增加任务、成员、军师、证据及交接；不需要把个人模式改写成另一份人设。第一次先用无害的小项目熟悉确认、提交和验收，再扩大并发。

## 开始一个项目

在新会话选择现有模式与已配置的模型，说明目标、输入、交付形式和验收。例如：“使用 Agent Team 检查这个本地示例，先列方案和验收；不同成员分别实现、复核，保留原文件。先读取 team_help start。”主沟通者可以使用任意已配置模型，不要求固定品牌或关闭思考。

先把缺失的输入、工具或授权说清楚。军师参与规划的项目可以先确立一个只产出计划的里程碑：通过用户确认后，由规划成员形成材料，规划与质量军师分别审查，独立验证人接受该版本，再解锁后续执行。军师的意见不等于用户授权，也不代替实际复现。

模型会生成结构化 V2 方案。按需创建必须同时在方案中选择 `on-demand`，并由部署配置启用。V1 方案仍保留手动派工方式。不要同时运行两个负责同一团队的引擎，也不要在团队暂时不可用时另建普通子代理重做同一批工作。

## 检查完整方案

确认前打开完整方案，核对真实模型连接与型号、思考档、成员职责及上级、实际加载的技能、任务依赖、输入输出、写入归属、独立验收人、资源和恢复策略。清楚说明哪些浏览器、设备、网络目标和操作允许使用；“授权充分”不会自动使所有宿主工具具备所需能力。

首次确认及扩大范围需要明确动作；没有回应不会自动成为授权。确认绑定当前方案版本。目标、验收或范围变化时检查新旧差异，避免用旧版确认批准新版。普通派工和恢复可在已确认范围内由程序继续。

模板中的 provider、model 和 reasoningEffort 是占位符，提交前必须替换为当前 DSH `list_team_models` 的真实输出。一个任务只能有一个有效执行者；独立交叉验证应明确登记为复核任务。成员不能接受自己的结果。

## 看懂团队状态

![真实宿主中的三栏团队视图](assets/team-desktop.png)

左栏显示主沟通者、军师、长期成员和真实上下级；中栏按组展示任务；右栏显示选中成员或任务的模型、技能和证据。角色列表反映当前团队，专家档案是另外保存的可复用模板。专家模板为空不代表当前团队没有成员。

“待命”表示当前没有模型请求，不表示成员记忆已删除。依赖未完成、资源被占用、等待复核、模型冷却及状态同步是不同情况。只有存在就绪任务却没派发时才应调查调度；不应为让所有成员显示运行而重复实验或制造工作。

任务提交之后仍需复核。已完成项进入档案，可打开执行编号、输入版本、产物及验收记录。计数表示任务状态，不能用成员人数、生成文件数或 token 数代替业务完成率。状态不可用时显示同步中或具体错误，不能把未知当作空闲。

“诊断与资源”可导出本地元数据：版本、编号和计数。它不导出目标正文、人设、技能全文、文件路径、模型连接或账单，也不自动上传。报告问题时优先提供该文件和最小合成复现。

## 调整模型和技能

在成员详情核对实际请求模型和下次生效的路由；队长可使用 `team_member configure_model` 原位调整。当前请求完成前保持原路由，之后采用新配置。成员身份、Session、已有任务、人设和选定技能继续保留。更换连接不是新建名字或新 Session 的理由。

上下文与输出上限由 DSH 模型配置提供。默认执行成员解析为模型实际支持的最高思考档；用户明确选择的主沟通配置保持原值。服务不可用时，应先区分额度、频率、账户并发、模型不存在或技术失败，只使用方案允许的替代连接。

技能先显示目录和用途，正文按任务选择。通常使用一个阶段流程和一至两个领域模块，总数与文本预算都受配置约束；不把整个技能库常驻到每个成员上下文。模式同名技能沿宿主优先级解析，选定正文固定摘要和版本。阶段切换先保存交接，再显式调整技能。

自定义技能放在自己维护的目录，通过 `additionalSkillRoots` 注册，详见[自定义说明](customization.md)及[技能专册](skills.md)。专业资料中的命令或工具仍需要实际安装、挂载、权限和真实调用验证，目录存在不表示环境已就绪。

## 处理阻碍与恢复

创建成员失败时保留已有任务与成果，查看派发诊断、目标版本、模型状态和工作集。不要反复提交相同错误字段。`team_help tools` 说明当前可用工具，`team_help network` 区分搜索提供方、成员工具上限、目标权限及实际网络问题。

文件路径应相对于当前成员工作区。私有输入缺失时，先核对前置成果是否验收并发布；容量不足时缩小任务工作集，不能只无限提高总量。显式声明的必要输入必须保留，不能因为目录通常被排除就丢失交接材料。

共享发布会检查基线、当前文件和已验收成果。冲突时保留双方，停止该次发布并调查；不要让队长把另一位成员的产物当成垃圾删除。应用内锁不能限制任意完整权限程序，浏览器、MCP 和外部命令仍需要系统层的独立约束。

宿主中断后打开同一会话继续。程序恢复成员、任务和回执；已完成任务不会因此自动重跑。外部操作是否成功如果不明，需要核对实际结果，再决定是否重试。旧原生事件的跨版本迁移是单独工作，不应直接修改历史日志让读取器跳过错误。

默认 bundle 会在用户的新一轮“继续”到达时唤醒待命中的未完成执行，保留原成员、执行编号和尝试次数。已经完成、仍在运行、有待投递消息或尚在冷却中的成员不会被重复唤醒；超过接续次数上限时保留阻碍供检查。它不会在手动停止之后擅自无限重启任务，也不能保证任意外部副作用都能自动恢复。

## 交付与停止

默认 bundle 在当前方案所有任务验收后，检查最终产物、发布并通知主沟通者汇报。部署者可以改为只通知或手动收尾。主沟通者应列出文件位置、验收结果、证据及仍未验证的部分；一次源码生成不能被表述为已经在真实设备或生产环境通过。

结束项目后成员待命不调用模型。停止或升级宿主前处理运行中的任务，保存交接，遵循[升级与回滚说明](installation.md)。本版本的支持范围及未验证能力以[兼容矩阵](compatibility.md)和[测试报告](test-report.md)为准。
