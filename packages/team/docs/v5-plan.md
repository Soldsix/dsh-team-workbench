# V5 规格与实现对照

## 概要

V5 在原有 DSH 会话、模式、模型、权限和工具扩展之上提供团队执行账本。主沟通者整理目标，双军师审核关键路线与证据，组长和长期成员承担执行，程序负责等待、派工、资源互斥和恢复。用户确认绑定具体方案版本，外部资料不能改写确认记录。

## 从需求到交付

```mermaid
flowchart LR
  U[用户目标] --> C[主沟通者整理技术问题]
  C --> P[完整方案与范围预检]
  P --> A[用户批准确切版本]
  A --> G[规划任务]
  G --> R[规划军师与质量军师独立决定]
  R --> V[非作者验证]
  V --> X[程序创建就绪任务所需成员]
  X --> W[分组执行与私有成果]
  W --> E[独立验收与冲突检查]
  E --> D[关键交付再次双审]
```

首次方案由主沟通者提交；确认后可以先执行只产出方案的规划里程碑。军师分别审查这个版本，独立验证人检查验收条件，通过后后续执行才就绪。主沟通者不必固定为某个型号，也不必固定关闭思考。

结构化方案列出全部成员、上级、实际模型、思考档、职责、角色指令、技能、任务 DAG、输入输出、验收项、独占资源、并发预算及恢复策略。预检拒绝未知模型和技能、任务自审、循环依赖、非法路径、超预算、过深委派及 V2 重用历史任务 ID。不能只确认“全权处理”就略去具体方案与资源条件。

任务使用目标版本、任务版本和执行编号关联；每个有效执行只有一个 owner。提交不代表完成，验收必须有证据和逐项检查，作者不能接受自己的结果。关键规划、路线、结果和交付需要规划与质量两份决定，再由独立验证人接受。军师要求修订时会通知独立复核人核实，不能等待两份批准才允许退回。退回后仅向沟通者发送一次持久通知，由其读取理由、核对工具影响并明确安排原成员的新执行；不会自动批准或无限重试。

目标变更保留旧历史和成果，不将旧授权自动继承到新项目；普通文件不能更改目标。服务内容限制、工具限制、授权范围和技术失败分别记录，不伪造背景，也不将某个模型的意见记成用户撤销授权。

## 成员与军师

长期成员保留身份、Session、创建配置、后续模型路由、角色变更、选定技能及任务记录。原位换模在下一请求生效，保留历史结果和成员 ID。模型的上下文与输出上限来自 DSH 连接配置，插件不顺手改全局默认值。

规划与质量军师只在关键任务提交后收到简短审查通知，读取证据、留下决定后待命，不领取执行任务。组长可以承担独立任务，并在已确认预算与层级内委派；按需调度先复用同名长期成员，只为就绪任务创建尚缺的 owner、reviewer、军师及祖先。

创建孙代理时，宿主恢复真实祖先会话并临时保留其驻留，不通过额外模型消息唤醒父级。父级即使快速结束也不会让创建依赖消失。全队共用任务板、额度与目标范围，下级不能扩大上级权限。

无任务、依赖未完成、资源被占用、待审核和模型冷却分别处理；程序等待不调用模型。按需创建不保证所有已规划成员立即出现，也不为显示运行而制造重复任务。可以配置 8、20、32 或更多成员，但实际请求数始终受团队、连接、模型和账户池约束。

## 文件与资源

每名隔离成员只在自己的工作区准备输入与写入成果。输入按任务选择，必要的显式产物目录可交接；大项目不再为每个成员盲目复制整个仓库。工作集超限会报告具体限制，保持原成果，先调整输入选择再重试。

成果提交生成不可变内容回执；独立验收后才能集成到共享目录。发布核对基础、当前内容与批准成果，同文件冲突保留双方，删除不作为隐式垃圾清理。进程内串行与 SQLite 跨进程锁共同保护协作发布；同团队另一个进程不能同时拥有写入权。

新建或修订任务时留存原始输入版本，复核不依赖共享文件仍保持原样。下游启动前先批量检查明确的依赖，再发布和准备其输入；预期内的已验收产物更新不会把交付流程卡住。无关文件改动、未验收结果、未知版本和冲突仍阻塞，并形成可操作的诊断。普通缓存复用仍按原输入检查，不能把“可以交接这些成果”混同于“任何新输入都能复用旧结果”。 同一成员可以在后续任务继续修改同一文件，早先提交始终由不可变归档校验；目录清理不使已归档成果失效。多阶段交接允许明确依赖链中的中间版本或最终版本，独立任务冲突及归档损坏仍会拒绝。

默认 bundle 在所有方案任务验收后校验并发布最终成果，再发送一条持久通知，让主沟通者汇总交付；重启不重复通知。部署者可将 finalDelivery 改为只通知或手动收尾。发布冲突时保留原成果并报告阻碍，不提前宣称共享文件已经就绪。

浏览器、设备与账号可通过 `exclusiveResources` 排他分配，持有至验收或明确释放。配置错误只形成一次持久诊断消息，不反复派出相同请求；工具范围错误不能通过换成 shell 绕过。

外部进程若持有宿主完整写权限，仍能绕过应用内协调。MCP、完整 shell、后台子进程与网络文件系统必须单独验证或隔离，当前版本不提供覆盖任意程序的全局文件写入防护。

## 记忆与效率

当前成员身份从持久团队记录重新注入运行上下文，角色、目标和技能均有版本；上下文压缩不依赖最初的自我介绍。方案只注入相关摘要与任务引用，完整成员表和历史证据按需读取。旧技能正文会从当前表面退休，原始 Session 仍保留记录。

技能目录先加载名称与用途，最多四个选定模块并受文本预算限制；模式自带技能可沿原优先级解析。技能阶段切换是显式选择，不自动混入另一项目授权、账号或人设。

任务创建、派发消息与回执按稳定身份去重；同一任务不因重启重复发布。已验收结果在复用前核对现有文件、环境和依赖。无法判断外部操作是否成功时，需要独立核对影响后才能重试，不能假设每个外部系统都有恰好一次语义。

额度或频率失败进入冷却，保留同一执行和成员；恢复通知不改变配置模型。已有后台作业由程序跟进，进程重启后不凭旧注册表假定外部命令仍在运行，也不自动重跑。

用户继续时，程序只唤醒当前目标里仍未完成且待命的原执行；活动成员、冷却及待投递消息会避免重复唤醒。已完成任务不接续。手动停止后不会自行无限恢复，接续次数受部署配置限制。

## 界面

采用 A 三栏与 C 分组：左侧为沟通者、军师、长期专家及真实成员树；中间为分组任务、负责人、复核者、依赖和等待；右侧为角色、模型、技能、证据与版本。完整方案始终可打开，当前团队与专家模板分开，状态缺失显示同步中。

任务支持搜索、状态筛选与逐页展开；成员支持紧凑排列、检索与孙代理层级。诊断页导出编号、版本与计数，排除目标正文、人设、技能全文、文件路径和连接配置，不自动上传。颜色与字体沿用 DSH，支持深浅主题、窄屏和键盘操作。真实流程截图见[界面说明](ui.md)。

## 未完成能力

以下能力不能被当作本版已有保证：跨机器分布式调度、任意外部工具的强制文件隔离、供应商实际余额和账单、项目 token／费用／时间硬预算、相似任务语义去重、自动推算所有下游失效范围、所有 MCP 的实机健康面板、真实设备与所有模型的能力验证。

`0.2.2-rc.1` 改变了模型选择、投影注册和 PTC 等接口，当前主包不支持。兼容适配需要独立构建与真实安装回归，不能只扩大 peer 范围。旧原生团队事件的全量迁移也不包含在本版部署动作中，详见[兼容矩阵](compatibility.md)。
