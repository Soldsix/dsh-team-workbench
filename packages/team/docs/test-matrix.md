# 验收矩阵与复现方法

## 概要

本表区分源码回归、安装后的真实宿主、真实模型项目和外部依赖。测试结果与版本见[测试报告](test-report.md)，机器可读摘要见发行证据文件；脚本模型只用于可重复的调度和错误路径，不能证明真实模型的专业质量。

## 源码与拒绝路径

| 场景 | 核对内容 | 证据类型 |
| --- | --- | --- |
| 目标确认与替换 | 完整字段、确切版本、旧确认失效、任务版本冲突、没有授权时拒绝执行 | 核心行为及记录快照 |
| 双军师与独立验收 | 军师不执行、自审拒绝、两份独立决定、证据与验收项完整 | 核心及工具行为 |
| 任务接续 | 原成员、执行编号、尝试次数保持；活动成员不重复唤醒 | 可控模型与冷重启 |
| 文件发布 | 基线与当前修改比较、大小写/路径别名、同文件互斥、冲突保留 | 并发、跨进程及内容回执 |
| 资源与取消 | 全队请求上限、共享账户池、排他资源、冷却、取消、释放 | 可控时钟及生命周期 |
| 技能 | 按需正文、数量/字节上限、同名优先级、内容版本、退休及恢复 | 核心与模式回归 |
| 工具 | 当前岗位清单、继承安全上限、输入与产物读取、分页、路径与哈希拒绝 | 核心、工具和兼容回归 |
| UI 状态 | 同步与故障、真实上下级、角色、任务筛选、500 条分页、键盘 | 客户端回归 |
| 发布类型入口 | 构建后运行 `npm run check:published-types`；独立 Host／Client 消费者核对属性类型，并拒绝缺失本地类型扩展 | 声明消费者及反向回归 |

## 安装后的真实宿主

`scripts/host-smoke.py` 通过已发布的 `dsh` profile 启动官方 npm 宿主，使用新的 home、随机端口和本地 HTTP 模型；它不启动 package bin 旁路，不读取用户模式正文，也不需要真实模型密钥。

| 场景 | 开关及观察 |
| --- | --- |
| 8／20／32 路真实请求重叠 | `--workers` 选择人数；HTTP 屏障要求全部独立执行请求同时在场，不能只按成员数判并行 |
| 孙代理与原位换模 | 真正的组长／下级关系；同一孙代理 A→B→A，请求型号改变，身份和 Session 保持 |
| 军师要求修订 | `--adviser-revision-fixture` 注入规划材料不足，复核人独立退回，沟通者明确重派原成员；只有该任务增加一次尝试，已完成工作不重跑 |
| 同文件顺序修改 | `--transform-input-fixture --serial-update-fixture` 由同一成员按依赖连续修改输入，原始输入与旧产物从归档核对，最终版本正确发布 |
| 未完成执行冷恢复 | `--pending-restart-fixture` 在写入前让成员待命，重启后发用户继续；执行和尝试保持，只发生一次待完成写入 |
| 已完成结果恢复 | 重启后比较完整归档中的任务与执行；成员不重跑，最终通知只有一条，最终文件内容保持 |
| 模式与技能 | `--mode-fixture` 使用三个合成模式，不读真实人设；同名技能由模式优先，未选择正文不进入沟通者请求 |
| 搜索与抓取 | `--network-fixture` 为每名成员调用真实网络工具与本地提供方；不等于公共搜索服务和凭据都已就绪 |
| MCP | `--mcp-fixture` 启动真实 stdio 桥并调用只读 echo，检查宿主停止后的子进程退出；不代表全部第三方 MCP 已通过 |
| 多模态传输 | `--image-fixture` 从孙代理实际读取 PNG，检查下一次模型请求的 image 内容；真实图像理解另用项目验证 |
| Windows 命令 | `--shell-fixture` 在孙代理私有工作区运行声明的 Node／Python 脚本与本地 curl，检查中文输出；明确批准完整程序执行，不能用该用例宣称仅路径受限目标也允许任意命令 |
| 自定义目录 | `--custom-profile-fixture` 加载完整示例配置与额外技能目录，选择后正文进入执行者，未选择不进入沟通者 |
| 浏览器 | 原生确认、完整方案、三栏、成员搜索、末尾成员详情、各页签、诊断下载、深色与窄屏 |
| 三小时稳定性 | `--soak-seconds 10800` 保持完成团队待命，定期冷重启并核对状态；不是三小时持续高负载或泄漏排除证明 |

复现时指定新的 `--run` 目录，保留其中的结果与合成快照，不重用旧日志冒充新一轮结果。使用 Python 依赖文件准备 Playwright 和 zstandard；Chrome 可由 `CHROME_BINARY` 指定，Node 由 `NODE_BINARY` 指定。

## 安装、配置与回滚

`scripts/test-install.py` 在新 home 执行计划、安装、显式自定义、错误安装回滚和卸载。检查原 provider 设置、模型／模式行、profile 字节、依赖目录与 Session 哨兵。助手默认仅计划，正式应用必须声明目标宿主已停止；脚本不会替用户停进程。

不支持的宿主在写 profile 之前拒绝。类型通过、源码构建通过和真实 npm 宿主安装是三个证据，不能互相替代。跨平台 CI 文件存在不表示该平台已有运行结果。

发布 CI 在 Windows／Ubuntu 与 Node 22.19／24.13.1 四组中，既安装各组重建的归档，也安装 `deployment` 中同一份待交付 `.tgz` 并做冷恢复。Git 发布前核对提交内归档的 SHA-256，防止用不同平台各自构建成功代替同一交付包的实际安装。结果以发布提交的实际 CI 为准。

## 真实模型与专业验收

真实模型项目应记录模型注册信息、任务版本、看过的图像、真实构建与运行结果、失败与返工。首稿与后续修改分开保存，不能把经过看图修订的版本作为一次生成的成绩。模型自己写的“检查通过”不能代替外部浏览器或可复现工具证据。

Three.js 示例分别用 `scene-smoke.py` 检查实际加载、拖拽、缩放和普通动画，用 `scene-detail.py` 采样 14 个细节视角，用 `scene-motion.py` 核对着陆收翅、绳端与弧垂、云影、重建和偶发灯塔／彩虹。三个脚本均接受 `--project <包含dist的目录> --output <新的结果目录>`；动作脚本针对第五轮 multiround 的具名对象，不能用于没有这些动作的首稿。后两个检查使用受控动画时间，细节检查还会调整相机；它们不代替正常用户交互或三小时实时时长验证。

测试范围不包括所有专业任务的成功、所有反代行为、任意外部进程的文件限制、真实供应商账单、全部移动设备及全量插件组合。未验证项和适配缺口必须随发行报告保留。
