# JSVMP 目标语义恢复

用于当前项目的虚拟化 JavaScript 样本。先确认目标函数、输入输出、客户端版本、资源摘要、运行环境和可观察结果；把样本标签、静态推断和实测结论分开。普通压缩、控制流平坦化、真正的字节码解释器及跨 WASM/Native 调用可能同时存在，不根据外观直接定性。一般原生虚拟机转用 [虚拟机分析](../team-vm-reverse/SKILL.md)。

## 采样与状态

1. 保存无插桩基线：资源加载顺序、入口调用、固定输入、时间与随机源、外部响应、最终输出及异常。再增加最小观察点；若输出、时序或分支变化，撤去观察点并缩小采样范围。
2. 从目标输出向前追踪到解释器入口，标出字节码生成或解密、常量池、分派器、宿主函数、退出及异常路径。动态代码和 Worker 分别登记资源摘要，不拼接不同版本的轨迹。
3. 定义可重放状态：PC、指令字节、寄存器或栈、调用帧、对象引用、异常状态、外部输入。每条轨迹记录执行前后状态、读写集合、字节码偏移和宿主调用结果；敏感输入使用可核对的受控引用。
4. 先恢复目标路径实际经过的指令：操作数解码、位宽、符号、跳转、调用、闭包、属性访问、缓存、异常与副作用。对每种指令设计能区分候选语义的最小输入；遇到自修改字节码或多层 VM 时固定解码阶段并单独编号。
5. 将已验证语义映射到稳定中间表示，保留原字节码偏移与宿主调用引用。需要跨语言实现时逐项核对 JS 数值精度、32 位位运算、UTF-16、属性枚举顺序、缺失值、强制类型转换和异常。目标路径以外的指令仍标为未知。
6. 选择可维护的目标实现：恢复为普通计算代码，或保留只执行必要指令的最小解释器。把设备和网络输入作为显式参数；若目标是纯算，按 [纯算验收](../team-offline-computation/SKILL.md) 核对运行依赖。

## 失败分流

| 现象 | 下一项可判定实验 |
|---|---|
| 加入断点后路径改变 | 对比未插桩基线和最少量日志，确认观察行为是否改变结果 |
| 同一指令得到不同值 | 核对对象别名、调用帧、外部状态和字节码解码阶段 |
| 轨迹一致而最终结果不同 | 比较异常、副作用、序列化及宿主函数的第一处差异 |
| 部分输入通过 | 为未见分支新增轨迹和向量，不把已覆盖路径扩写成完整 VM |
| 新版脚本失效 | 建新资源版本，比较解释器、字节码与宿主接口三个层次 |

## 交付与验收

交付样本与环境清单、VM 状态定义、指令表、偏移映射、目标路径覆盖、独立实现、逐步差分向量及未知项。开发样本和未参与恢复的验证样本分别报告；验收者能定位首个分歧，并能从证据判断计算一致、协议有效或仍依赖浏览器的范围。
