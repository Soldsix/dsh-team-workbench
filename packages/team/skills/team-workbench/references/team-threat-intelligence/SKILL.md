# 安全情报与新漏洞研究

将搜索问题绑定当前资产、软件/SDK 版本和任务目标。公开资料可以提供假设，只有当前环境的版本、配置、可达条件和复现实验能支持当前结论。使用联网工具时记录检索日期与原始链接；优先官方公告、上游提交、原始研究和会议论文，再参考看雪、吾爱破解、CSDN、国际安全论坛中的原作者材料。

## 资料判断

1. 去重转载并记录作者、原始地址、发布日期、修改日期、样本版本、端类型、代码/样本可用性、许可证及研究者实际证明的结论。论坛贴、推测与官方配置说明分别标记。
2. 对已公开漏洞按“名称匹配 → 版本可能受影响 → 条件满足 → 授权环境复现 → 修复回归”推进。CVE 标识、CVSS 严重度、EPSS 预测及 KEV 收录各记录自己的含义，不互相代替，也不能仅凭分数断言当前部署受影响。
3. 对疑似新漏洞建立线索、可证伪假设、最小异常样本、根因、实际影响和修复验证。可使用代码审计、补丁差异、解析器与协议状态测试或模糊测试；尚未确认根因或影响时保留为线索，不标记成 0day 成果。
4. 新版 SDK、挑战或规则出现时先比对官方发布说明与当前安装样本，定位受影响的模块及向量。已经验证的旧版本成果保持原版本，不自动套用新版，也不因网络文章覆盖项目内实测结果。
5. 研究结论进入长期技能前，以独立样本或当前项目复核；更新只写通用决策方法，具体字段、密钥、URL 和版本证据留在项目记录。

## 交付

交付来源表、资产与版本对应、假设及实验结果、未验证条件、修复/缓解依据和下一次触发检查的条件。研究任务可输出“无可复现影响”的结论，但必须说明覆盖了哪些样本和前置条件。具体技术选型继续使用 [公开方案研究](../team-research/SKILL.md)。
