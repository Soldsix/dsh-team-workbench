# 设备指纹 SDK 逆向

这里的 SDK 指采集和处理设备/浏览器特征的业务 SDK。目标是解释指定版本的行为并产生可验证结果。沿用用户确认的样本、设备、账号与服务范围；仅在团队分工或实验设计缺口出现时，分别补读 [团队工作流程](../team-workflow/SKILL.md) 或 [实验规范](../team-experiment/SKILL.md)。

## 明确交付层次

根据用户需要确认：字段字典、静态调用链、动态证据、算法复现、注册状态机、跨版本差异或完整测试实现。将每层转成独立验收；恢复采集函数不代表已经复现远程风险决策。

盘点 SDK 载体及边界：网页脚本/Worker/WASM，Android AAR/DEX/SO，iOS framework/xcframework/Mach-O，以及 SDK 所属应用、远程配置和服务端接口。保存文件摘要、包/构建版本、发布渠道及依赖。无样本时输出准备清单和本地练习方案，不编造某厂商实现。

## 分层调查

1. 建立初始化、采集触发、异步任务、持久缓存、上传、返回处理的主链，标注可观测边界与未观测节点。
2. 建立字段表：原名、类型、来源 API/函数、归一化、默认值、采集条件、作用范围、生命周期、上传位置与证据。区分直接标识、派生摘要、安装随机值、环境特征、完整性证明和行为数据。
3. 从发送数据回溯序列化、压缩、加密、签名、时间/随机量，再正向追踪至少一项字段。将采集值、上传值和服务端返回 ID 分开命名。
4. 用对照实验检验重启、清缓存、重装、权限拒绝、系统升级、离线和重试。记录哪些字段变化、哪些仅缓存命中、哪些属于服务端重新分配；不要从相关性直接推导设备绑定规则。
5. 按需要复现可观测的客户端处理和本地验证器；挑战/证明依赖服务端时保留接口与测试替身，标明真实服务尚未验证。

## 专家并行与交接

按当前平台选择 [网页指纹](../team-web-fingerprint/SKILL.md)、[Android 指纹](../team-android-fingerprint/SKILL.md) 或 [iOS 指纹](../team-ios-fingerprint/SKILL.md)；仅在协议、算法或运行时观测形成独立缺口时，分别补读 [注册协议](../team-registration-protocol/SKILL.md)、[加密参数](../team-crypto-parameters/SKILL.md) 或 [运行时分析](../team-runtime-instrumentation/SKILL.md)。各组共用字段编号和证据记录；禁止各自重复采集同一已验证样本。

## 验收

- 每个声称已恢复的字段都有静态定位或可重现运行证据，未知字段明确列出。
- 关键链路至少有完整输入、中间表示、最终输出及失败反例；另有未参与推导的测试样本。
- 指纹稳定性与碰撞实验有明确定义和样本范围；不把“同一哈希”直接称为“同一物理设备”。
- 结论区分客户端已恢复、服务端已观测和服务端未知，产物包含版本差异与复用条件。
