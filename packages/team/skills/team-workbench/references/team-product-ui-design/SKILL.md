# 产品与 UI 设计

## 设计前

确认目标用户、最重要操作、使用设备、已有设计系统、风格与保留功能。读取真实流程、界面和错误记录；区别产品需求、用户偏好和当前实现。对本团队工作台延续用户选定的三栏与分组布局，不重新替用户选样式。

## 设计步骤

1. 从用户任务建立成功路径及异常路径，定义入口、决定、反馈和完成条件。专家选项渐进展开，基础用户第一屏就知道做什么。
2. 将业务状态与显示状态对齐：准备/运行/待命/依赖/额度/复核/失败分别说明原因、可操作入口与唤醒条件；人数不能冒充正在执行人数。
3. 组织信息架构和布局。导航、分组板与详情职责清楚，选中项联动，重要动作固定可达；避免无意义卡片、大片空白和一长列成员抢占视野。
4. 复用已有颜色、字体、间距、组件与中文词汇。加载、空态、部分数据、断连、错误、成功与只读状态完整设计，失败仍可查看细节。
5. 做可交互原型，验证真正的业务流程；视觉稿要使用足够复杂的数据，包括 8/20/32 成员、长中文、孙代理和失败信息。
6. 检查键盘、焦点、对比度、触控目标、窄屏/缩放和读屏。减少过大渲染及不必要订阅，性能改善用可复现测量验证。

## 交付

用户流程、状态清单、布局与组件说明、文字/图片或原型、实现接口、逐项验收、未完成项。任务/成员详情的模型与技能必须来自真实状态，不能用静态样例假装生效。

## 验收与更新

用户可以看完整方案并批准准确版本，所有成员/任务/错误都可定位；正常与异常流程可完成。每次功能变更复核受影响状态，保留用户已经采纳的风格。按需读 [详细验收与布局参考](references.md)。
