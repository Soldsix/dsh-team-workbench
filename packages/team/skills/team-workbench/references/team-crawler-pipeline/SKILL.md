# 批量协议采集

输入是一条已在当前环境验证的请求或公开接口、明确字段需求、允许的请求范围和资源约束。记录无账号、游客初始化、授权身份三种实际访问等级；单条请求成功之后再设计批量运行。网络握手和计算分属 [注册协议](../team-registration-protocol/SKILL.md) 与 [纯算验收](../team-offline-computation/SKILL.md)。

## 工程步骤

1. 建任务键：平台、地区、身份级别、端/接口版本、商品 ID、变体和采集窗口。任务发现、请求执行、解析、存储各有持久状态；保存原始响应的摘要与解析版本以便复核。
2. 明确分页、游标和结束条件，分别设计全量与增量流程。去重同时覆盖任务、请求和商品记录；价格、库存等时间敏感字段保留采集时间和地区。
3. 对 Cookie、设备状态、令牌、计数器及注册结果指定所有者。会改变同一会话状态的操作串行或采用经验证的协调方式；工作线程不能互相覆盖。网络未知结果的有状态请求先查询实际状态，再决定是否重试。
4. 依据目标可接受负载配置并发、速率、超时、退避、熔断和冷却，分别限制模型研究并发、浏览器/设备资源和 HTTP 请求量。性能提升以稳定成功率及数据完整性为目标，避免为吞吐重复请求失败页面。
5. 用检查点恢复未完成任务，记录失败类型与重试次数。身份过期走续期路径，接口版本变化暂停受影响队列并重新采样，解析失败保存样本。确定性业务拒绝进入人工或研究队列，不无限重试。
6. 对输出做字段校验、跨页重复检查、SKU/币种/地区一致性检查和抽样回读。将请求成功率、字段覆盖率、去重率、落库延迟与资源消耗分开显示。

## 验收

交付持久队列与状态定义、单条基线、速率配置、断点恢复结果、失败样本、字段来源与时效、数据质量报告。实际授权环境完成声明规模的批次后，比较预期任务数、完成数、缺失和重复；重启后能从检查点继续，且不会将登录受限字段误报为匿名可得。
