# 加密参数与签名链

先明确用户需要解释哪段数据处理，沿用本任务已确认的权限；团队交接条件缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。输入包括对应版本程序、可控测试数据、请求字节与可观察边界；不凭高熵或字符串外观判断算法。

## 恢复步骤

1. 将链路拆成规范化、序列化、编码、压缩、摘要/MAC、加密和封装。保存每层精确字节、长度与输入条件；区分 UTF-8 字节、UTF-16 代码单元与字符长度。
2. 从 API、常量、调用图和动态输入输出互证算法与模式。记录 key 来源、派生函数、salt、IV/nonce、padding、tag、AAD、计数器与字节序；只有明确观察后才能填写参数。
3. 追踪时间、随机数、路径、请求头和正文排序对签名的影响。比较缺失字段与空字符串、重复键、Unicode、浮点表示、URL 编码和换行，定位第一处字节差异。把动态值的生成、取得、过期与并发更新来源写入输入表，不将测试固定值用于真实协议。
4. 用隔离测试密钥和随机量实现最小复现；受控固定随机源只能用于测试。真实秘密保持受控引用，不写入通用技能、聊天示例或专家共享记忆。
5. 验证已知与未见向量，覆盖失败校验、损坏密文、错误参数和边界长度。能解密一条数据不代表已恢复密钥生命周期或完整协议。

## 验收

交付逐层格式、参数依据、实现和成功/失败向量；每个未知参数显式列出。优先成熟密码库，避免自行实现密码原语；恢复自定义运算成为独立问题时，再按平台补读 [原生](../team-native-reverse/SKILL.md)、[JS](../team-js-reverse/SKILL.md) 或 [JSVMP](../team-jsvmp/SKILL.md) 方法。服务端接受与客户端计算一致分别验收；最终运行依赖按 [纯算与协议直连](../team-offline-computation/SKILL.md) 报告。
