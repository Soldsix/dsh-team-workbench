# 质量与性能

沿用本任务已确认的验收；团队交接条件缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。先把“好用、快、可靠”写成可测指标。基线、输入规模、设备、模型、网络与工具版本明确；不从单次成功宣称没有缺陷。

## 验证路径

1. 按真实入口验证用户主路径，选择能暴露当前风险的单元、集成、界面或实际模型用例。受控适配器、测试替身、练习样本与真实业务分别标记。
2. 覆盖取消、超时、部分失败、重启、并发冲突、旧数据与资源释放。持久项目需核对历史、配置、原模式和插件功能；不能仅检查页面打开。
3. 性能测试先定位瓶颈，分别测首次与复用、模型请求与工具等待、CPU/内存/设备占用、输入上下文与输出开销。报告分位数、分母和失败率。
4. 对 8、20 或 32 路团队验证全树额度、共享设备、队列恢复及没有重复执行。资源受限时测排队和公平性；并发数量大不自动代表更快。
5. UI 使用实际宽屏和小屏窗口，检查中文、字体、键盘、焦点、错误提示与长内容。高级设置展开后可自由配置，默认流程只显示当前决策需要的信息。

## 验收

每项指标写明实测值、环境、阈值及证据。失败先复现最小原因，再修复和局部复查；已通过且无关联变化的检查直接引用。最终列明通过、未执行与剩余限制，不能把模拟器结果、代码审查或静态检查替代真实运行结果。
