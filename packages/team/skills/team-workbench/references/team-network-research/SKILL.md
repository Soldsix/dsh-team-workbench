# 联网研究与工具诊断

## 先确认要解决的问题

继承当前目标与授权。把研究收敛为一个问题、已有证据、所需版本和期望产物。最新接口、工具版本、库行为、平台规定或市场判断需要联网核查；离线已验证事实优先复用。不要因为搜索服务失败就改写用户的授权。

## 工具顺序

1. 工具缺失先查看当前模式工具和 `team_help({"topic":"network"})`，不能猜工具名。PTC 只调用实际提供的绑定。
2. 用 `web_status({})` 查看本地注册、配置和近期失败；它不联网，不证明远程服务可用。聊天模型、聊天密钥和辅助搜索服务是独立配置，切换执行模型不能代替修复搜索连接。
3. 用 `web_search({"queries":["具体技术 版本 官方文档"]})`，最多四个不同查询。直接查已知官方 URL 时，可在范围允许下 `web_fetch`，不为增加步骤重复搜索。
4. 核对原始页面、发布日期、实际版本与许可证。官方文档、源代码、研究论文优先；论坛线索继续追到原始证据。搜索摘要只作线索，不能当实验结论。
5. 来源有用且任务允许下载时，通过当前可用的 MCP 或已授权命令工具获取固定 commit/tag，记录来源、校验摘要和工作区目录。读取不能等同执行外来安装脚本。
6. 成员分配不同研究问题；共享搜索记录和去重键。下游拿已发布的来源包和结论，避免各自重复搜相同关键词。

## 失败恢复

无原生结果块、凭据缺失、HTTP 429、冷却、DNS/TLS 和权限拒绝分别处理。冷却不反复调用；备选搜索只使用部署已明确配置的提供者。跨 origin 跳转先核对目标完整 URL 和范围。原范围内其他分析继续，记录缺失的外部证据。

## 交付与验收

交付问题答案、来源 URL、版本/日期、适用条件、实验与资料的区别、未知项。执行者复核来源能否支撑结论；另一成员检查关键推断。没有结果和没有执行搜索必须明确区分。

需要诊断分支和可复用表格时再读 [详细参考](references.md)。
