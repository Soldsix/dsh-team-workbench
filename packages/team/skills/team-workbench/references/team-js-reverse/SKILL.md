# JavaScript 逆向

沿用本任务已确认的目标；团队交接方法缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。先确定需要恢复的函数、协议或页面行为；保留实际加载的原始资源及摘要，不将格式化副本当作原始证据。

## 分析路径

1. 盘点 HTML、脚本、模块、Worker、iframe、动态字符串执行和 WASM。利用 source map 前先检查其版本与构建是否匹配；缺失资源与加载顺序记录为输入条件。
2. 从用户动作、网络发送或已知输出双向定位入口，建立调用图和异步时序。先截取最小相关切片，按模块或不同假设分工，避免多人同时遍历整包。
3. 对字符串表、常量解码、控制流、动态属性和闭包逐步命名。AST 变换保留原节点映射；每次只做可验证变换，检查异常、getter、求值次数、作用域和副作用，不能以“看起来等价”删除分支。
4. 用真实运行环境采集输入、中间值与输出；记录时间、随机数、编码、缓存与网络响应。仅在确认对应依赖后提取纯计算片段，补环境过程保留缺失 API 与失败原因。
5. 以多组向量进行原实现与复现差分，覆盖空值、Unicode、负数、整数溢出、异常、并发调用和缓存复用。未见输入作为独立验收。

## 特殊分支

自定义解释器、浏览器环境采集或密码与签名细节成为独立问题时，分别补读 [虚拟机逆向](../team-vm-reverse/SKILL.md)、[网页指纹](../team-web-fingerprint/SKILL.md) 或 [加密参数](../team-crypto-parameters/SKILL.md)。不把运行时观测的一个分支当作全部逻辑。

## 交付与验收

提交入口地图、关键函数含义、原始位置映射、最小可运行复现、差分向量和未覆盖路径。代码恢复的可读性、输出一致性和真实场景接受情况分别报告。原始文件、重命名注释、变换脚本与产物版本均可追溯。
