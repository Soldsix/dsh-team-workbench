# 云、容器与供应链

沿用本任务已确认的云账号/订阅、区域、集群、命名空间、仓库、流水线和测试身份；团队分工缺口出现时再补读 [团队工作流程](../team-workflow/SKILL.md)。先读取已有配置与用户资料；安装到主机的技能不等于拥有云写入权限。

## 检查路径

1. 建立代码、依赖、构建身份、产物、部署身份和运行资源的链路，保存配置/锁文件/镜像摘要。区分测试与生产环境及外部托管服务。
2. 核对最小权限、角色信任、身份委派、网络暴露、存储访问、秘密引用与审计记录。检查容器实际运行权限、挂载、服务账号、策略和命名空间关系，不能只看镜像扫描分数。
3. 对依赖与镜像漏洞核对实际组件、可达路径和修复版本；对构建来源、制品摘要、签名或证明核对信任配置和验证者，避免只检查是否存在文件。
4. 在隔离环境用测试资源验证权限与策略。任何会部署、计费、读取秘密或改变配置的步骤先核对现有范围；先生成差异与回滚方案，再执行已获准操作。
5. 分工按身份、运行环境、网络与流水线；共享资源标识和证据版本。多个代理不得同时修改同一 IAM 或集群策略。

## 验收

提交配置证据、具体影响、最小修复差异、应用顺序和恢复条件。复核原风险已被阻断，正常构建/部署仍可用；记录费用资源与临时对象的清理。工具和云语义在项目启动时通过 [官方资料核对](../team-research/SKILL.md)，不以旧模板替代实际配置。
