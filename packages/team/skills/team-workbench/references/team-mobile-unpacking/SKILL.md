# 移动端加固与样本恢复

沿用本任务已确认的应用、构建和设备权限；团队交接方法缺失时再补读 [团队工作流程](../team-workflow/SKILL.md)。优先获取相同版本的源码、符号或开发调试产物；只有需要研究运行时装载内容时才选择对应观测。保存原包摘要，所有恢复产物另存。

## 分析步骤

1. 区分压缩归档、应用分包、平台包加密、动态代码加载和第三方加固。列出原始入口、加载器、静态可见代码及缺失内容，记录判断依据。
2. Android 关注多 DEX、分包、ClassLoader 和 JNI 库的装载时机；iOS 关注 Mach-O slice、加载命令、模块映射和调试构建可用性。工具先核对系统/架构兼容，不把不同平台的恢复方法混用。
3. 在明确允许的测试环境观察目标模块何时变为可读、由何处加载，限定记录范围。保留文件偏移、内存地址、权限、映射区间和模块摘要。
4. 恢复副本后检查头、段或表边界、方法/类数量、导入与重定位信息、字符串及目标入口。可被工具打开不等于内容完整；以具体目标函数可定位、可反汇编和运行证据对齐判断。
5. 将补头、修表和重建步骤做成可重复的派生过程，保留差异及失败样本；不要修改唯一原始输入。无法恢复的动态内容列出触发条件和下一项观测。

## 验收

交付原包与恢复副本的映射、装载时序、恢复方法、完整性检查与限制。复核者能够定位预定 SDK 函数并关联到实际执行。只有获准重打包/重签名时才进行该项验证，重签名环境变化单独记录；后续交给对应平台指纹或 [原生分析](../team-native-reverse/SKILL.md) 技能。
