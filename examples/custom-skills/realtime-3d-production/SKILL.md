# 实时三维场景交付

## 适用与输入

用于可交互微缩场景、产品展示、程序化建模与实时视觉。先确认相机与交互、比例与坐标、核心构图、材质与光照风格、必须可见的内部细节、动画、目标浏览器、性能预算与交付形式。用户要求无 UI 时，控件、图例和调试面板不能出现在成品画面。

核对现有依赖、锁文件、构建与预览入口、模型是否支持图片、浏览器可用性及任务工具权限。使用当前项目版本的官方文档；不能把不同版本的 addon 名称混用，也不能为了运行构建擅自扩大目标权限。

## 规划与并行

1. 先固定共享坐标、单位、地面与水面高度、相机方向、体量、命名和组件接口。每个接口写明输入、返回值、可用 helper、动画注册与错误报告。
2. 用资产清单对应全部验收项，登记每项归属和空间范围。地板、水面、共享灯光和全局控制各只有一个维护者，防止重叠、不同单位与重复底座。
3. 拆成可以独立提交的文件；角色与任务写明上游版本、输入、输出、禁止修改的共享接口、验证人与验收条件。建模、灯光、技术美术和验证可并行，文件写入不能重叠。
4. 保留首轮不可变提交、样本和工具版本。后续视觉修改建立新版本，复用原成员与已确认事实，不把多轮成果写成一次生成。

## 建模与材质

5. 主次体量和空间关系先于细碎物件。透过玻璃能看到内部，需要真实开口、适当透明排序和可辨识的舱内摆设；一层半透明方块不能替代完整室内。
6. 用统一调色板、材质规则和轮廓粗细约束并行成员。高调不等于过曝，柔和不等于所有表面同色；检查水、混凝土、金属、玻璃、潮线与阴影的层次。
7. 先在真实浏览器编译和渲染 shader，记录错误。透明物体单独检查 depthWrite、排序、背面和遮挡；反射、折射、色彩空间与 tone mapping 必须结合截图判断。

## 动画与性能

8. 统一一条时间循环与动画注册，使用秒和 delta，保存基准变换，避免累计漂移。每帧不反复创建几何、材质或纹理；对象与事件监听在销毁时释放。
9. 先测固定视角的 draw calls、三角形、几何与纹理数量、帧间隔和加载时间，再优化。相同几何与材质的大量重复物体可评估 InstancedMesh；修改实例矩阵后按当前 API 标记更新。[官方说明](https://threejs.org/docs/pages/InstancedMesh.html)
10. 静态合并必须保持世界变换、材质、属性、阴影及可见性，属性不兼容时分组或保留。排除动画对象及其动态祖先、骨骼/变形、实例与需要独立透明排序的对象；不能为了减少 draw calls 冻结旗帜、船、鱼或雨。合并 addon 及其返回值按当前版本核对。[官方说明](https://threejs.org/docs/pages/module-BufferGeometryUtils.html)
11. 验证优化前后的画面、动态与交互，记录同环境样本。renderer.info 是观测入口；多渲染 pass 时先明确计数口径。[官方说明](https://threejs.org/docs/pages/WebGLRenderer.html)

## 多模态复核与迭代

12. 外部驱动真实构建，再获取主视图、反向、近景室内、窄屏与至少一段动态观察；保留截图、相机参数、时间、版本及错误。读取失败必须报告，不能用文件名猜画面。
13. 视觉复核人先看实际图片，再提出可定位的问题：对象、画面区域、问题、预期、对应文件与优先级。作者和复核人分别记录结论，关键取舍由军师基于证据决定。
14. 修改只分给对应维护者，下一轮重新构建和拍图；比较新旧证据，确认是否真的改善。静态截图不证明帧率、动效或全部视角，模型静态审查不证明页面已跑通。

## 交付与恢复

交付锁定源码、依赖、启动说明、许可证、验收矩阵、真实截图、性能口径和未完成项。检查无控制台/着色器异常、无意外网络依赖、相机拖拽/缩放、分辨率变化、动画实际改变场景、资源释放及用户指定的无 UI 要求。

失败先区分构建、接口、资源、WebGL、材质、视觉和性能问题。保留可运行基线与原始产物，仅重做受影响部分，不删除另一位作者的成果。未实测的平台、设备和帧率不能标作通过。
